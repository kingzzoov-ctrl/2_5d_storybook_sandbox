### ✅ F-4 ε 截断正态标准差(**已修复,2026-11-12**)

手册 L568 写 $\varepsilon \sim \mathcal{N}(1.0, 0.12^2)$,即 **σ = 0.12**;
`attributes.ts` 的 `EPSILON_SIGMA` 曾写作 `0.122`。

差 0.002(1.7%),且 ε 被截断在 `[0.80, 1.25]` 内,**对最终品质的影响 < 1%**,不改变任何分档概率到可观测程度。

**裁决结论:改代码为 `0.12`,与手册对齐。** 理由:这不是「有意取 0.122 以匹配截断后实际标准差」——
追查原始注释发现它写的是 `N(1.0, 0.1222)`,其中的**末位 `2` 是上标(Unicode `U+00B2`)**,
即原意就读作 σ = 0.122,与常量自洽、但与手册不符 ⇒ 属于**誊写错误**,不是调参。
既然两处本就不一致,取「手册值」是唯一有权威依据的选择。

改动:`server/src/alchemy/attributes.ts` 的 `EPSILON_SIGMA` 0.122 → 0.12,
注释由单行扩为一段说明(记手册出处、誊写错误判断、影响 <1%);
同步 `tests/WS-06.test.ts` 的断言与 `scripts/data-conformance.ts` 的对照注记。
**零风险**:ε 的截断区间未变,分档阈值未变。

## 二、手册自身的问题(不是代码错)

审计过程中发现两处**手册内部矛盾**。这类必须单独列出 ——
把它们当成代码 bug 去改,会让代码变得「照错的抄」。
脚本对这两条判为「无法判断」,不判代码错。

### H-1 手册 §5.3 正文举例与 §3.2 配表冲突

手册 L565 举例:「如普通松木 $V=10$,**寒铁锭 $V=45$**,**秘银锭 $V=85$**,Boss 遗物 $V=250$」。

但手册自己的 §3.2 配表写的是:
- L91:`| 113 | 寒铁矿石 | ... | $V=40$ |` ← 与正文的 45 不符
- L92:`| 114 | 秘银矿石 | ... | $V=70$ |` ← 与正文的 85 不符

而且 L565 说的是「寒铁**锭**/秘银**锭**」(半成品),§3.2 的 113/114 是
「寒铁**矿石**/秘银**矿石**」(原料)——**两者本就是不同物品**。

代码取的是**配表值**(113=40、114=70、101=10、708=250),这是合理选择:
配表是逐条列出的权威数据,正文举例是叙述性引用。

**裁决建议**:确认 113/114 应为矿石还是锭。若配表里没有独立的「锭」ID,
则 L565 的举例应改为「寒铁矿石 $V=40$、秘银矿石 $V=70$」。

### H-2 手册 L40 声明的 μ 区间与 §3.5 表自相矛盾

手册 L40 写「摩擦阻尼系数 μ ∈ [0.40, 0.98]」,
但 §3.5 表 L223 给 322 强粘蜂蜜减速毯的 **μ = 0.35**,**低于自己声明的下界**。

代码忠实取了 0.35。测试因此**不能**用 L40 的区间去逐块校验 ——
已改为只校验手册未逐块列举的两个缺省值(`FLOOR_DEFAULT_MU`/`BARE_GROUND_MU`)。

**裁决建议**:确认 322 的 μ 是 0.35(则 L40 区间下界应改为 0.35)
还是 0.40(则 §3.5 表笔误)。

## 五、审计方法

**判据是手册原文,不是代码常量。** 这是本审计与「代码自检」的根本区别:

```ts
// ✅ 正确:期望值抄自手册 L19
eq(TICK_HZ, 20, '高频帧');

// ❌ 错误:同义反复 —— 改数值时两侧一起变,永远绿
eq(TICK_HZ, PHYS.TICK_HZ, '高频帧');
```

测试里的期望值全部是**从手册逐字抄来的字面量**(带行号),
因此手册不在场也能跑,且改代码会让它变红。

### 三个常见陷阱(本次都踩过,已修)

1. **注释里写 `*/` 会提前结束块注释**。在描述正则时尤其容易,
   例如写「不能用 `/\*\*P[1-9]\*\*/` 这种严格写法」会把注释截断,
   后续代码被当成顶层语法 → `SyntaxError`。改用文字描述正则。

2. **行偏移算错会静默错位**。玩具表表头在 L161、`221` 行在 L162,
   若行号算成 `161 + (id−221)` 就会整体错一行 —— 而错位后**所有行都非空**,
   不会报错,只会得到一份整体错位一行的「全面不一致」报告。
   现在 `rowOf()` 会**回验该行确实以该 ID 开头**,不匹配即返回 `null`。

3. **不要凭印象手写对照表**。第一版玩具配方表是手抄的,
   32 条里错了 11 条 ID(把 152 记成 131、把 155 记成 112 等)——
   而这些错**看起来像是代码错了**。正确做法是从手册材料**名称**反查 ID 生成,
   即让手册当唯一来源。
