## 二、⭐ 最严重:S11 的**幽灵转发边**造成了真实漏报

这是本批唯一**实测复现了错误数字**的缺陷。

### 2.1 复现

在 `server/src/alchemy/pixel_icon.ts` 末尾加一行**字符串**:

```ts
export const __g = "see export { ICON_SIZE } from './attributes.ts'";
```

门禁输出:

```
基线      同义反复候选:命中 32 条(白名单 32 条)
注入后    同义反复候选:命中 31 条(白名单 32 条)(白名单失真 1 处)
          ✗ 同义反复白名单失真(1 处,应修正):WS-06::ICON_SIZE(已不再命中,应移出白名单)
```

**候选 32 → 31,静默丢失一条。**

### 2.2 机制

`buildReexportMap` 跑 `stripCommentsOnly`(保留字符串)+ 正则,于是抓到这条**假转发边**:

```
pixel_icon.ts::ICON_SIZE  →  attributes.ts
```

而 `attributes.ts` 里**没有** `ICON_SIZE` ⇒ `numExports.has('attributes.ts::ICON_SIZE')` 为 false
⇒ 该常量解析失败 ⇒ 候选消失。

**这是掩盖方向**:与 S26 的 R6 幽灵依赖同类,但后果更直接 ——
**它让 S11 少报候选**,而 S11 的存在意义正是「把同义反复候选暴露出来」。

### 2.3 三种形态全部有效

| 形态 | 命中数 |
| :--- | ---: |
| 双引号 | 31(**掩盖**) |
| 单引号内嵌 | 31(**掩盖**) |
| 模板字符串 | 31(**掩盖**) |
| 注释里(对照) | 32 ✓ 未受影响 |

### 2.4 会自我暴露吗?—— 目前是巧合

当前 `32 命中 = 32 白名单`,`未登记候选 = 0` ⇒ 被掩盖的候选**必然**在白名单里 ⇒ 触发失真自检 ✓

**但这是巧合**:REVIEW-8 曾出现过「未登记 1 条」的状态(`WS-06::ICON_SIZE` 刚浮现时)。
**若那时有幽灵转发边,掩盖会完全静默 —— 没有任何告警。**

## 三、修复:抽出通用的**代码态扫描**

新增 `extractCodeStateBlocks(text, 'import' | 'export')`,单遍扫描:

- 注释**整段跳过**
- 字符串字面量**整段跳过内容**(这正是旧实现漏掉的)
- 只在**代码态**认 `import` / `export` 关键字,然后**不限长度**推进到 `}` → `from` → 路径字符串
- `names` 片段**剥注释后再切分** —— 否则 REVIEW-8 的缺陷 A(注释被当名字)会回归

`parseNamedImports` 与 `buildReexportMap` 都改用它,旧的正则实现删除。

> **「不限长度」是关键**:本仓有 47 名的大转发块,用固定窗口截断会漏。
> 我自己在诊断脚本里就犯过这个错(见 §五)。

### 3.1 验收(四项判据全过)

| 判据 | 结果 |
| :--- | :--- |
| ① 三种幽灵形态**不再**掩盖 | ✓ 全部 32 → 32 |
| ② **阳性对照**:真转发链仍被解析 | ✓ 从 `index.ts` 移除 `ICON_SIZE` ⇒ 32 → **31**(证明链在生效) |
| ③ REVIEW-8 缺陷 A 不回归 | ✓ WS-06 命中仍 32 |
| ④ 现网数字不变 | ✓ 32/32、24/50、1141 条断言 |

**判据 ② 最重要**:修复若让真链也失效,S11 会对 WS-06 重新变瞎 —— 那就把 REVIEW-8 的成果一起丢了。

### 3.2 顺带加固 `scanForbidden`(噪音方向)

`:459` 的「向前 300 字符找 `import`/`export`」启发式把 **`export const` / `export function` 这类声明也算成了导入语句**。实测:

```ts
export const msg = "failed from '../combat/damage'";   ⇒ 误报 import-no-ext
export function f() { return "from '../a/b'"; }        ⇒ 误报
```

加固:要求 `import`/`export` 之后**紧跟 `{` / `*` / `type {`**(真导入/转发的形态),排除 `export const` 等。

**现网 0 例;方向是噪音(误报),不是掩盖,危害较小。**

## 六、把教训提升为**通用规范**

同一个根因(`stripCommentsOnly` 保留字符串)**已在三个不同调用方各证伪一次**:

| 轮次 | 调用方 | 症状 | 方向 |
| :--- | :--- | :--- | :--- |
| REVIEW-9(S26) | `reachableClosure` | 幽灵依赖 | 掩盖 |
| REVIEW-11(U12) | `buildReexportMap` / `parseNamedImports` | 幽灵转发边 | 掩盖 |
| REVIEW-11(U12) | `scanForbidden` | 假 import-no-ext | 噪音 |
| (待定) | `backlog.ts` `STALE_PROBES` | 假「条目过时」 | 噪音 |

**规范建议(请纳入 CR-13)**:

> **凡对源码做正则,必须在代码态文本上做。**
> `stripCommentsOnly` **保留字符串内容**,只适用于「路径本身在字符串里」的场合,
> 且必须配「关键字在代码态、取值在字符串」的语义 —— 见 `extractCodeStateBlocks`。
> 违反此规范的后果分为两类:**掩盖**(少报,危险)与 **噪音**(多报,吵但可见)。
> 掩盖方向优先修。
