## 三、`:740` 的定性:确认为**真同义反复**

### 3.1 机制

```ts
// server/src/world/fluid.ts:35
export const OBSIDIAN_ID = 110;

// 同文件 :620 —— 相变产物**直接取该常量**
const product = kind === FluidKind.HOT_SPRING ? PUMICE_ID : OBSIDIAN_ID;

// tests/WS-01.test.ts:740
for (const p of products) eq(p.obj, OBSIDIAN_ID, '产物是黑曜石 110');
```

**实现把常量塞进产物,断言再拿产物比常量** ⇒ 常量改成任何值,两边同步移动。

### 3.2 注入实测

注入 `OBSIDIAN_ID` `110 → 999`:

```
基线       [WS-01] 50/50 通过
注入 999   ✗ 熔岩遇水凝结为黑曜石 110 — 黑曜石 ID 期望 110 / 实际 999
           ⇒ 失败 test 仅 1 个
           ⇒ :740 所在 test「水与熔岩相邻:不混合,而是走相变路径」**仍通过**
```

**`:740` 在常量变化后完全没反应 ⇒ 恒真确证。**

## 四、⭐ 但覆盖**没有缺口** —— 这是我差点报出的假缺陷

### 4.1 一个陷阱

注入后只有 1 个 test 失败,报的是 `:664 eq(OBSIDIAN_ID, 110, '黑曜石 ID')`。
`:679/:680 eq(products[0].obj, 110, '产物是黑曜石')` **没出现在失败里**。

**若据此判「:679/:680 也无牙齿」,就是假缺陷** —— 因为
`shared/testing/harness.ts:162` 的 `eq` 失败即 `throw`,同一 test 内
**`:664` 先 throw,`:679/:680` 根本不会执行**。

> 这与我修 `WS-06:552/553` 时遇到的是**同一个短路问题**。
> 已在 REVIEW-9 记为建议 **S30**,本批再次命中 —— 说明它是**通用陷阱**,不是个例。

### 4.2 独立证明:中性化 `:664` 后再注入

把 `:664` 临时换成注释(只动这一行),再注入 999:

```
中性化后基线    [WS-01] 50/50 通过
注入 999 后     ✗ 熔岩遇水凝结为黑曜石 110 — 产物是黑曜石 期望 110 / 实际 999
                ⇒ :679/:680 **变红 ⇒ 有牙齿** ✓
```

### 4.3 结论

| 断言 | 形态 | 性质 |
| :--- | :--- | :--- |
| `:664` | `eq(OBSIDIAN_ID, 110)` | 锚定**常量本身** = 110 ✓ 有效 |
| `:679/:680` | `eq(products[0].obj, 110)` | 锚定**行为结果** = 110 ✓ **有牙齿** |
| `:740` | `eq(p.obj, OBSIDIAN_ID)` | **恒真**(冗余)✗ |

**行为被 `:679/:680` 的字面量 110 完整守住 ⇒ 覆盖无缺口。**

`:740` 是**冗余且恒真**的一条:**它不承担覆盖责任**,删掉或改字面量都不影响缺陷检出能力。

**这是关键区分**:
- 「恒真断言」≠「覆盖缺口」。前者是**冗余噪音**,后者是**漏检风险**。
- `:740` 只是前者。把它报成「WS-01 有缺陷」会冤枉这个套件 —— 317 条断言里 316 条是健康的。
