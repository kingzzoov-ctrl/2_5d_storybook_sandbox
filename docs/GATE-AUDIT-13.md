## 二、失效检查清单(按危险度排序)

### 🔴 D1 信任边界:实参整体透传时**没有**文档所称的"回退接口级"

| 项 | 内容 |
| :--- | :--- |
| **在哪里** | `checkClientTrust`(`verify.ts:1254-1335`),字段提取循环 `:1274-1301` |
| **管什么** | 反作弊汇点 `room.ts` 的 `this.ac.inventory/move/attack(...)` 实参里,受管字段的取值表达式是否来自客户端 |
| **文档怎么说** | `:1176-1177` 白纸黑字:"实参**整体透传**(如 `applyMove(id, pkt)`,字段名不出现)时字段级无法定位,**此时回退接口级** ⇒ 只要实参引用客户端就算全部命中。**保守多报,不漏。**" |
| **反例** | 把汇点 `this.ac.inventory(userId, { tick, ops, allowedSources: this.grantedSourcesFor(userId), ... })` 整体换成 `this.ac.inventory(userId, input as never)` |
| **结果** | **退出码 0**。输出:`✓ 汇点 1 个 / 受管字段 3 个 / 实测取自客户端 0 处` |
| **是否失效** | **是**。代码里**没有任何回退分支** —— `:1276 if (!want) continue;` / `:1278 if (at < 0) continue;` / `:1282 if (!fm) continue;` 三处 `continue`,没有第四处。`grep` 该函数体 84 行,无"回退"字样 |
| **为什么危险** | 整体透传是**一次完全合理的重构**(把对象直接往下传,少写一遍字段)。重构后门禁报"0 处取自客户端",**报告反而更干净** —— 而实际是 3 个受管字段全部失控。这不是"漏报",是**把漏报显示成好消息** |

补充实测:别名形态 `this.ac.inventory(userId, pkt as never)`(配 `const pkt = input`),
同样退出 0。文档 `:632` 声称字段级判定顺带修掉了别名漏报 —— 那是在**字段名出现**的前提下成立,
整体透传时依然全漏。

**修复建议**(改 `checkClientTrust`):在字段循环**之后**补一个分支 ——
若 `want.length > 0` 且本次调用**一个字段都没匹配到**(`matched === 0`),且实参文本里出现
`clientParam` 匹配的标识符(或实参根本不是对象字面量),则把该方法的**全部**受管字段
推入 `found`(保守多报)。判据:

```
const isObjectLiteral = /\{\s*$/.test(args.slice(0, 40));
if (matched === 0 && (!isObjectLiteral || clientParam.test(args))) {
  for (const field of want) found.push({ method, field, expr: '<整体透传,回退接口级>' });
}
```

这样 `inventory(userId, input)` 会报 3 处红,与文档承诺一致。

| 项 | 内容 |

③ 每个受管方法的字段数组不得为空。三者任一命中即 `fail`。

| 项 | 内容 |
| :--- | :--- |

### 🔴 D5 容量账本失败走 `failures += 1`,**不打印 `✗`**

| 项 | 内容 |
| :--- | :--- |
| **在哪里** | `checkContent`(`verify.ts:2814-2820`),关键行 **`:2818 failures += 1;`**(只 `console.error(' ⚠ ...')`) |
| **管什么** | 位域容量余量(物品 ID / 地砖槽位等),`ratio > 0.9` 即失败 |
| **反例** | 把阈值改成 `> -1` 迫使告警触发(副本内) |
| **结果** | **退出码 1,但 `✗` 行数 = 0**,`⚠` 行数 = 3 |
| **是否失效** | **判据没失效**(退出码正确,CI 能抓)。失效的是**证据通道**:这次失败在输出里**没有 `✗` 标记** |
| **为什么危险** | 全仓所有其它失败都打 `✗`,而 `:2905` 的测试失败摘录、以及人和 AI 的"grep ✗"习惯,都以 `✗` 为准。**唯一一条不打 `✗` 的失败,恰好是位域余量** —— 它一旦触发,输出里只剩一行 `⚠`,极容易被当成"告警、非阻塞"而略过。而且它**不在** `runTests` 的 `fail()` 汇总里,阅读"❌ N 项失败"时对不上账 |

把 `console.error(' ⚠ ...')` 保留为附加上下文。一行改动,消除唯一的不一致通道。

### 自检脚本 `scripts/gate-selfcheck.ts`
