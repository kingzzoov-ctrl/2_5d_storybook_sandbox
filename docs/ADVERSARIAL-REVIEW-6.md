### 2.3 实证推翻了我自己在 REVIEW-5 写下的「第一实参会漏」

REVIEW-5 §4.4 我写了边界:「只识别 `eq/near` 的**第二实参**;若常量写在第一实参会漏」。

**这句话本身没错,但我据此暗示它是个缺口 —— 现在实证发现:它不是缺口,而是正确的语义选择。**

我用**括号配平**正确切分实参(修掉正则 `[^,]+` 不能含逗号的老问题),
统计所有实参位置的候选:

```
门禁抓到的(第二实参)     =  75
其它实参位置             = 153
```

第一眼像「漏报 153 项」的大缺口。**于是我去查这 153 项的对照物是什么**:

| 对照物性质 | 数量 |
| :--- | ---: |
| **含数值字面量**(如 `eq(FLOOR_SLOT_MASK, 0x3f)`) | **153** |
| 不含字面量(需人工看) | **0** |

**153/153 全部健康。** 例:

```
WS-01:63   eq(FLOOR_SLOT_MASK, 0x3f, '槽位掩码应为 6 位')
WS-11:498  eq(STACK_REACH_Z, 0.3, '伸手抓取高度 0.30 格')
WS-FND-06:944 near(BUDGET_BASE, 8.5, 1e-12, '基数')
```

这是**最健康的写法**:常量在被测位置,对照**手册事实(字面量)**。
这正是 REVIEW-4 建议 S8 要达到的形态。

**所以「只查第二实参」是对的**:第二实参是「期望值」位置,
同义反复只可能发生在那里 —— `eq(实现值, 被测常量)`。
`eq(被测常量, 字面量)` 是**反向**的、正确的锚定。

> 这是本会话**第 5 次**靠实证拦住自己的判断,也是**第一次拦下「文档里已经写好的结论」**。
> 前四次拦的是「即将报出的缺陷」,这次拦的是「我已经当成事实写进交付物的一句话」。
>
> 具体教训:**153 这个数字单独看像重大缺口,配上「对照物性质」才看出它全是健康形态。**
> 只报数量不查性质,就是又一次「34:1 误报」。

### 2.4 真缺口:只有 `ok(...)` 不被覆盖

探针 D 确认:`ok(CONST === 1)` 形式**门禁不查**。这是**真实且刻意**的范围限制:

- `ok` 的实参是**布尔表达式**而非「期望值」,没有「第二实参」这个语义位置
- 要覆盖它需解析任意布尔表达式,复杂度高、误报风险大
- 实测 `ok` 形态里**没有**同义反复(REVIEW-2 的 G-2 `ok(spring.state.cooldown > 0)`
  是**单侧边界**问题,不是同义反复)

**结论:保持范围不变,把这一点写清为已知边界**,而不是扩成解析器。
