# GAME-VISION —— 北极星与现状差距(唯一入口)

> **本文是每轮开工前必读的第一份文档。** 它回答三个问题:
> 1. 这个项目**要做成什么**(愿景原文 = `2_5d_cartoon_sandbox_plan.md`,105 KB,仓外 `~/Downloads/`);
> 2. **玩家打开手机能看到什么**(体验验收,可看可测);
> 3. **现在到哪了**(逐项差距 + 证据 + 谁在做)。
>
> 判据/门禁/环境的铁律在根 `AGENTS.md`;子系统深度设计在 `docs/WS-XX-*.md`;
> 具体设计图在 `docs/WORLD-DESIGN.md`。

## 0 一句话愿景(照抄手册标题)

> **2.5D 精致绘本风·高自由度多人欢笑沙盒**:自由造物 × 实时欢笑互坑 × 奇幻狩猎 × AI 万物炼金。

四条支柱(手册 §一):

| 支柱 | 玩家的话 | 工程上意味着 |
| :--- | :--- | :--- |
| **自由造物** | 「我能把这块地变成任何样子」 | 320 物品可采集/合成/建造;地形可改(铺装/抬挖/引水) |
| **实时欢笑互坑** | 「我和朋友在同一屏上瞎搞」 | 同屏多人 + 刚体举投 + 35 种整蛊玩具 + 派对模式 |
| **奇幻狩猎** | 「外面有活的、能打的东西」 | 8 群系 × 24 野生物 + 8 Boss;驯养/掉落/破防团战 |
| **AI 万物炼金** | 「我随便组合,它给我造个新东西」 | LLM 定性 + 本地算法定量,产物可缓存可复现 |

**目标形态**:手机浏览器打开一个网址就能玩(`http://<服务器>:5173/`),触屏可操作,世界有大片野地、城镇、山丘、溪流、树木、动物、怪物、可交互的 NPC。

### 2.3 结构性教训(为什么会跑偏)

1. **没有顶层文档**:仓里有 100+ 份审计(`ADVERSARIAL-REVIEW-*`、`TASK-*`、`GAP*`),
   却没有一份"愿景 ↔ 现状";每次开工都从**欠账清单**往下做,没人从**玩家看到什么**往上对。
2. **没有根 `AGENTS.md`**:规则散在 `.pi/agent` 与各文档里,新会话读不到"这一轮该推哪条 V"。
3. **没有维护项目记忆**:跨会话只记得"门禁要绿",不记得"要做成什么游戏"。
4. **验收口径偏工程**:判据大量是"模块被 import 了""计数为 N",很少是"玩家屏幕上出现了什么"。
   ⇒ 本文件 §1 的七条就是为此补的**体验验收**。

## 3 路线图(里程碑 + 可机检验收 + 并行车道)

| 里程碑 | 内容 | 验收(必须可测/可看) | 车道 |
| :--- | :--- | :--- | :--- |
| **M1 世界是真的** | chunk 下行 + 改动同步 + 客户端渲染服务器块 | 两端块字节逐块一致;盖一块,客户端 ≤1s 可见(`WS-FND-182`) | A |
| **M2 世界是满的** | `obj` 立牌(墙/灯/箱/台)+ 植被(树/草丛) | 截图出现树冠绿与建筑色;`WS-FND-183` | B |
| **M3 世界是活的** | 每格群系 + 8 群系刷怪表 + 野生物分区 | 每个群系刷出的怪种 ⊆ 该群系 `BIOME_SPAWN`;命令可查 | C |
| **M4 有城镇与 NPC** | 城镇几何(墙/门/屋顶/家具)+ NPC 实体 + 一条可完成任务 | NPC 存在、可对话、任务从"未完成"变"已完成" | C |
| **M5 有玩法循环** | 主线六步状态机 + HUD 一行指引 | 每步一个可机检状态(`WS-FND-18x`) | D |
| **M6 有山丘与溪流** | 地形隆起/凹陷工具 + 流体下坡 + 溪流与瀑布 | 挖渠引水,水真的流到低处(已有流体场,补地形工具) | D |
| **M7 同屏多人** | 第二个人进得来、看得见彼此、能互坑 | 两个浏览器实例互见 + 举投一个玩具 | 待定 |

**并行纪律(避免撞车)**:
- 一条车道一个**文件所有权**,跨车道只通过**纯函数签名**对接(见各车道简报)。
- 车道之间的接口一旦改动,**同一轮**同步更新 `docs/GAME-VISION.md` 的本表与 `AGENTS.md`。
- 任何一轮结束必须:①`typecheck ≤ 257`;②相关套件全绿;③**本文 §1 的某一 V 从 ❌/🔧 变 ✅ 或写明为什么没变**。
