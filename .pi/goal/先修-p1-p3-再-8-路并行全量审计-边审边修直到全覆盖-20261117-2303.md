## Acceptance criteria(全部可客观核验)

1. **P1 已修**:不带任何 `--strict-*` 跑 `node scripts/verify.ts` 时,新增欠账会让门禁**失败**;带 `--lenient` 才只告警。README/HANDOVER 的门禁命令与实际口径一致。
2. **P3 已修**:存在判据证明「连续两次 `use_item` ⇒ 账面各减一次」,且注入(去掉退款/去掉权威读口/改成扣两次)会变红并完成字节还原。
3. **审计全覆盖**:`docs/AUDIT-W34.md` 列出被审计文件全集与每路范围;`server/src/**`、`client/**`、`shared/**`、`scripts/**` 下的**每个生产 `.ts` 文件**都至少被一条审计覆盖(给出文件→路的映射表与文件总数),无遗漏。
4. **发现已分流**:所有发现按 P0..P3 归档;`P0`/`P1` 全部有「已修 + 判据 + 注入证据」或「明确写清为何不修」;`P2`/`P3` 有落点或理由。
5. **门禁全绿**:`node scripts/verify.ts --all --strict-reach --strict-taut --strict-inert --strict-selfcheck` **exit 0**、行首 `✗` **0**;README/HANDOVER/§九 自洽;类型 ≤ **261 条 / 129 指纹**。
6. **已推送**:`git rev-parse HEAD` == `git ls-remote origin main`;工作树仅 `?? .pi/`。
7. **完成报告**:覆盖率(文件数 / 已覆盖数)、发现总数与分布、修复数、剩余登记项、以及每路一句结论。

## Boundaries

- 不加依赖;禁 `enum` / 构造函数参数属性 / `namespace` / 装饰器;相对导入以 `.ts` 结尾。
- 审计 subagent **只读**;修复由主代理做,改动走最小 diff。
- 不为凑绿放宽判据:禁 `eq`→`ok(...)`、禁重试包裹、禁删断言、期望值不许取自被测模块。
- 注入还原**只用原始字节写回**并校验 SHA256;禁 `git checkout` / `git reset` / 通配删除。
- 不 commit `.pi/`;不 `git push --force`;**不并发跑 `verify.ts --all`**(只在收口跑)。
- 类型错误不得增加;`shared/testing/harness.ts` 永不改。
