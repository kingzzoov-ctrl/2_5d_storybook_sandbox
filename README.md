```

```

`verify.ts:2972` 早已写明「tsc 恒红 ⇒ 拿它当门禁 = 一个永远红的门 ⇒ 没人会看它」——
**那个取舍是对的**。但它漏掉第三条路:**错误数稳定 ⇒ 它可以是基线**(现值读 `node scripts/typecheck.ts` 与 `scripts/typecheck-baseline.json` 的 `total`,本文件不手抄)。
判据因此从「零错误」变成「**不增加**」,与本仓既有的 `content-lock` 同一思路。

```
错误数 > 基线      ⇒ **红**(引入了新类型错误)
出现基线没有的指纹 ⇒ **红**(哪怕总数没涨)
错误数 < 基线      ⇒ **告警不红**(变好了;基线该刷新)
typescript 未装    ⇒ **跳过并说明**(本仓默认零依赖,不是缺陷)
```

★ **为什么比「指纹多重集」而不是只比总数** —— 这是实测,不是推理:
```
修掉 1 条 + 新引入 1 条 ⇒ 总数不变
  只比总数    : 2 → 2          ⇒ ★ **绿**(放过了!)
  比指纹多重集: 新增 1 / 消失 0 ⇒ ✓ 红(抓住了)
```
指纹 = `文件 | 错误码 | 归一化消息`,**不含行号**
(含行号则"上方插一行"会让其后所有错误行号 +1 ⇒ 表现为全部消失+全部新增 ⇒ 天天误报)。

★ **它不替代 `vite build`**:后者查语法与模块解析(实测输出里 `error TS` 命中 **0** 次,确实不查类型),
本锁查类型,两者互补。

## 时间口径:帧数即时间(★ 2026-11-25,`docs/DECISIONS.md` D-26)

**世界时间 = `frameCount × DT`(不读挂钟)。** 名义 tick 率已由 20Hz 改为 **32Hz**(`TICK_MS = 31.25ms`),
所以「帧长」是**物量纲的标称**,不是墙钟承诺 —— **「1200 游戏秒」不等于「1200 墙钟秒」**:
两者分属**两个钟量纲**,不许互相顶替。31.25ms 确实落在宿主定时器粒度网格上(Windows 默认 15.625ms:
31.25 = 2 × 15.625 是整数倍),**但真实循环不由网格决定**:本机**真实 WS 循环**实测
`tickMean = 34.6ms` / `28.9fps` ⇒ **倍率 ≈ 1.11**(1200 游戏秒 ≈ 1328.8 墙钟秒),
即 `play` / `soak` 启动打印给出的 **≈1.11 倍**,**不是 1**(「网格精确 ⇒ 两边一致」这条推理至少在本机不成立);
**Linux / 生产部署必须在目标机实测后回填**,不要假设 1:1。(旧 20Hz 在本机实测 62.77ms/帧 ⇒ 20 / 15.93 = **1.2555**。)

时长一律以**秒**声明、帧数由 `secondsToTicks(n)` 派生(换 tick 率时**只有帧数动**)——
判据 `tests/WS-FND-177-tick32-seconds.test.ts`。

```bash
node scripts/play.ts       # 启动 5 秒后打印「实测节拍」:tick 间隔 / 实际 fps / 世界钟×墙钟倍率
node scripts/soak.ts --minutes 1 --clients 2   # 汇总行同款一列(倍率 = 标称帧率 ÷ 实测帧率)
```

- **必须用墙钟**(与人 / 进程 / 网络有关):自动存档周期、心跳与离线判定、连接 / 握手超时、
  重连宽限、会话时效、炼金缓存时效、拍卖类限时(本仓尚无实现,口径先立)。
- **必须用游戏秒**(与世界推进有关):冷却、DoT、buff 到期、赛局时长、打盹 / 露水、昼夜。
- **两钟交界处必须选一个并保持同源**:跨钟比较要显式换算并写单位(`DT` 是唯一的换算处),
  不许把「帧数」当「秒」用。

逐条现状(`文件:行`)与判据见 `docs/DECISIONS.md` D-26 表 ·
`tests/WS-FND-175-clock-convention.test.ts`。
